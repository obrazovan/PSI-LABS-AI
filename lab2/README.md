# Лабораторная работа №2: Приложение с графическим интерфейсом (UI) для генератора экзаменационных билетов

Десктопное приложение с графическим интерфейсом (GUI) на Python (Tkinter/ttk) для автоматизированного распределения экзаменационных билетов среди студентов с сохранением полной истории в Microsoft Excel (`results.xlsx`).

## 🏗️ Архитектура и принципы SOLID / Clean Code

Проект спроектирован по принципам чистой архитектуры:

```text
lab2/
├── .venv/                           # Виртуальное окружение Python (изолированные зависимости)
├── requirements.txt                 # Зависимости: openpyxl, python-docx, pytest
├── pyproject.toml                   # Конфигурация проекта и pytest
├── run.py                           # Точка входа для запуска GUI
├── README.md                        # Документация лабораторной работы
├── sample_data/                     # Эталонные демонстрационные файлы
│   ├── students.xlsx
│   └── tickets.docx
├── students.xlsx                    # Рабочий список групп и студентов
├── tickets.docx                     # Рабочий список билетов с вопросами
├── src/
│   └── ticket_gui/
│       ├── __init__.py              # Экспорт публичного API
│       ├── models.py                # Модели Student, Ticket, ExamResult
│       ├── parsers.py               # ExcelStudentReader и DocxTicketParser
│       ├── storage.py               # ResultJournalStorage (results.xlsx с lock-обработкой)
│       ├── service.py               # TicketService (бизнес-логика, идемпотентность)
│       ├── __main__.py              # Запуск: python -m ticket_gui
│       └── ui/
│           ├── __init__.py
│           ├── main_window.py       # Главное окно MainWindow (выпадающие списки, кнопка)
│           └── result_dialog.py     # Модальное окно ResultDialog с поддержкой ESC
└── tests/
    ├── conftest.py                  # Pytest фикстуры с генерацией тестовых файлов
    ├── test_models.py               # Тесты моделей и их валидации
    ├── test_parsers.py              # Тесты парсинга Excel и Word (включая пропуск дефектных билетов)
    ├── test_storage.py              # Тесты Excel-хранилища и обработки блокировок
    ├── test_service.py              # Тесты идемпотентности (повторный выбор -> тот же номер)
    └── test_ui_logic.py             # Тесты состояний интерфейса и привязок клавиш
```

### Принципы SOLID в реализации:
- **S (Single Responsibility)**: Чтение студентов (`ExcelStudentReader`), парсинг Word (`DocxTicketParser`), запись журнала (`ResultJournalStorage`), логика правил (`TicketService`) и графический интерфейс (`MainWindow`, `ResultDialog`) строго разделены по отдельным модулям.
- **O (Open/Closed)**: Возможность добавления других парсеров или форматов хранилища без изменения интерфейса и бизнес-логики.
- **L (Liskov Substitution)**: Строгие протоколы и неизменяемые модели данных (`frozen=True`).
- **I (Interface Segregation)**: Минималистичные и сфокусированные интерфейсы классов.
- **D (Dependency Inversion)**: `MainWindow` и `TicketService` зависят от абстракций репозиториев, легко заменяемых моками в тестах.

## 📊 Формат файлов

### 1. Входной файл `students.xlsx`
- Каждый лист соответствует одной группе (имя листа = имя группы).
- Строка 1: `A: Фамилия | B: Имя`.
- Строки 2+: Записи студентов.

### 2. Входной файл `tickets.docx`
```text
Билет 1
1. Текст первого вопроса.
2. Текст второго вопроса.
3. Текст третьего вопроса.

Билет 2
...
```

### 3. Выходной файл `results.xlsx`
| A (Группа) | B (Фамилия) | C (Имя) | D (Номер билета) | E (Дата и время) | F (Повтор) |
|---|---|---|---|---|---|
| ИВТ-21 | Иванов | Иван | 2 | 2026-11-07 15:10:00 | нет |
| ИВТ-21 | Иванов | Иван | 2 | 2026-11-07 15:15:00 | да |



